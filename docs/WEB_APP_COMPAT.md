# 웹과 앱이 다르게 동작하는 이유

같은 코드라도 웹은 브라우저에서, 앱은 Android의 Hermes 엔진과 네이티브 네트워크 위에서 돌아간다. 그래서 웹에서 성공해도 앱 동작은 보장되지 않는다.

## 빌드 전 검사

```bash
npm run check         # 위험한 코드와 빠진 .env 값 검사 (몇 초)
npm run check:bundle  # Android·웹 번들을 실제로 빌드 (몇 분)
```

`npm run check`는 APK를 만들기 전과 PR을 올리기 전에 실행한다. 규칙은 `scripts/check-app.js`에 있다.

통과해도 실제 동작이 보장되는 것은 아니다. 파일 업로드, 녹음, 카메라, PDF를 바꿨다면 **폰에서 직접 확인**한다.

## 금지 규칙

| 쓰면 안 되는 코드 | 앱에서 생기는 문제 | 대신 쓸 것 |
|---|---|---|
| `fetch('data:...')` | Android에서 URL 생성 단계에서 실패 | `base64ToBytes()` |
| `new FormData()`에 `{ uri, name, type }` 파일 추가 | Expo의 `fetch`가 지원하지 않아 실패 | `FileSystem.uploadAsync`의 `MULTIPART` |
| `document`, `window`, `navigator`, `localStorage` | 앱에 없어 실행 중 오류 | `Platform.OS === 'web'` 분기 안에서만 사용 |
| `<div>`, `<span>` 같은 HTML 태그 | 앱 화면이 멈춤 | `View`, `Text` |
| `http://` 주소 | 폰이 암호화되지 않은 요청을 차단해 조용히 실패 | `https://` |
| `import.meta`, `process.env[이름]` | 앱 번들에서 값을 읽지 못함 | `process.env.EXPO_PUBLIC_이름` |
| `Alert.alert` | 반대로 **웹에서** 아무것도 뜨지 않음 | `appAlert()` |

## 환경변수

`EXPO_PUBLIC_` 값은 **빌드할 때 앱 파일 안에 글자 그대로 들어간다.** 그래서 다음 문제가 생긴다.

- `.env`는 git에 올라가지 않아 팀원마다 내용이 다르다. 같은 코드도 **누가 빌드했는지**에 따라 기능이 켜지거나 꺼진다.
- `.env`를 고쳐도 이미 설치한 APK에는 반영되지 않는다. **다시 빌드해야 한다.**
- EAS 빌드는 빌드를 실행한 컴퓨터의 `.env`를 사용한다. 그 컴퓨터에서 `npm run check`로 값을 먼저 확인한다.
- `.env`에 값을 넣어 동작을 바꾸는 방식은 쓰지 않는다. 예전에는 `EXPO_PUBLIC_USE_RN_FETCH=1`을 전제로 파일을 전송했지만, 이 값이 없는 빌드에서는 조용히 실패했다. 지금은 이 값이 필요 없다.

## 앱에서는 되는데 웹에서 안 되는 경우

브라우저는 서버가 허용한 사이트에만 응답을 보여준다(CORS). 앱에는 이 제한이 없어서, 같은 서버도 앱에서는 되고 웹에서는 막힐 수 있다.

| 기능 | 웹 | 이유 |
|---|---|---|
| CLOVA 음성 변환 | 불가 | CLOVA가 브라우저 요청을 허용하지 않음 |
| 서버 워터마크 | 불가 | 서버가 브라우저 요청을 허용하지 않음 (기기 내 워터마크로 대체됨) |
| 푸시, 위급 자동 알림 | 불가 | 웹에는 앱 푸시 토큰과 백그라운드 작업이 없음 |

## 플랫폼별 코드를 새로 넣을 때

1. 공용 코드에 웹 전용 코드를 섞지 않는다. 분기가 필요하면 `if (Platform.OS === 'web')` 안에 둔다.
2. 브라우저 객체를 쓴 파일은 분기를 확인한 뒤 `scripts/check-app.js`의 `WEB_GUARDED_FILES`에 추가한다.
3. 실패를 `catch`로 삼키지 말고 사용자나 로그에 남긴다. 앱 전용 오류가 안 보이는 가장 흔한 이유다.
